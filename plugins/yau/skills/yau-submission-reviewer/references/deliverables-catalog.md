# 丘奖 Skill 家族输出契约（必须产出 × 按需产出）

> 读者：使用本技能家族完整服务一名学生/一篇论文的教练或执行 agent。
> 本契约规定"跑完一次算不算交付完成"的标准。判定词、报告骨架与渲染管线沿用
> `review-report-template.md` 与 `../assets/report-style/README.md`。

---

## 一、必须产出（三件套 + 渲染）

对一名学生/一篇论文做完整审查时，以下三件**缺一即未完成**；每件均渲染
tian2 三格式（`../scripts/render_report.py`）作为交付版。

### M1 · 论文审计报告（内容层）

对论文本身的学术审阅。内容合同：
- 结构对照：官方章节顺序 + 学科八要素（题目/摘要/背景现状/材料方法/结果/讨论/参考文献/作者贡献），缺哪个章节写哪个；
- 学科评审标准扫描（`subject-criteria-2026.md` 中该学科的提交前硬要求）；
- 逻辑与证据问题**定位到章节/表号/行**：推导自洽性、数据与图表一致性、摘要与正文结果一致性（摘要引用正文不存在的结果 = 最高优先）、引文可溯源性；
- 学生可解释性风险点（答辩最可能被问倒的段落，列 5–8 条）；
- 做得好的部分（如实写，供保留）。
- 主责：`yau-paper-writer` + `yau-data-analysis-tutor` 的审阅视角；报告骨架同
  `review-report-template.md`（判定词 pass/revise/blocked，must-fix 按严重度排序）。

### M2 · 参赛缺项报告（材料层）

即本技能的标准审查报告：12 项清单逐项判定 + `check_report_pdf.py` 机检附件
（含查重版 = 提交版 sha256 核对）+ 依据与待核实。结构严格按
`review-report-template.md`。

### M3 · 整改行动与验收清单（合并跟踪件）

把 M1、M2 的全部 must-fix 合并为**一张可执行表**，这是学生/学管实际拿去干活的文件：
- 六列：问题（含证据定位）/ 应补内容 / 负责人 / 最晚日期 / 验收标准 / 状态（未动/进行中/待验收/完成）；
- 按取消资格风险 → 内容缺陷 → 形式问题排序；
- 附以提交截止为 D-0 的倒排时间表（盖章 D-7、终稿冻结后查重 D-3、提交 D-1）；
- 复审时**在原表上更新状态列**，不另起新表——它同时是验收记录。

### 渲染要求

三件均出 HTML/PDF/DOCX；文件命名 `<学生或项目简称>-<交付件名>-<YYYY-MM-DD>.<ext>`，
同名归档于该学生工作目录。

## 三、场景速查（默认组合）

- **提交冲刺（截止前 ≤14 天）**：必须三件套 + O5（致谢页几乎总缺）+ O13
- **答辩准备期（入围后）**：O6 + O7 + O8，模拟一轮后补 O9
- **立项/中期**：O10 + O11 + O12 + O3
- **AI 痕迹整改**：O4 + O5（配合致谢页模板三情形表述）

## 四、通用纪律（所有产出共用）

1. 判定词只用 `pass / revise / blocked`；★ = 取消资格级；证据必须定位到材料具体位置。
2. 红线四条：不代写、不预测获奖/晋级、不替学生断言事实（独立完成/无偿等由学生自行确认）、
   不用取消资格恐惧做措辞。
3. 学生均为未成年人：一切产出只落学生本地工作目录，不进任何对外渠道。
4. "可以先做待填写版"类产出必须显著标注哪些格子是占位、由谁填。
