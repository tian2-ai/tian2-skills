# Answer frameworks — how to answer well

Three qualities every good defense answer has. Use these to critique the student's mock answers.

## 1. Specific, not vague
- Bad: "It improved performance." Good: "Macro-F1 rose from 0.71 to 0.79, +0.08, significant at
  our n=4,217 by a paired test."
- Bad: "The model learned the pattern." Good: "Attention concentrates on tokens X and Y, which
  matches the domain expectation that …".

## 2. Owns the work
- Name what is yours. "The architecture is standard; the contribution that's mine is the
  failure-mode analysis / the new loss term / the cross-domain import."
- On AI: layered disclosure (see /yau-ai-compliance) — admit the tool, claim the idea.

## 3. Doesn't overreach
- Match the claim to the evidence. "My design supports correlation, not causation, because …".
- "I don't know" → "I don't know, but I'd test it by {concrete method}." Never blank, never bluff.
- Don't claim universality ("works for everything") — name the assumptions.

## When stuck
- Mishear/unsure: "Let me make sure I understand — are you asking about {restate}?"
- Genuinely don't know: own it + propose a test. Judges respect this far more than a bluff.
- Never blame the mentor for a methodology choice.

## Critique template (for mock mode)
```
Q: <question>
Answer quality:
  Specific?    ✓/✗  <note>
  Owned it?    ✓/✗  <note>
  No overreach?✓/✗  <note>
Fix: <one concrete improvement>
```
